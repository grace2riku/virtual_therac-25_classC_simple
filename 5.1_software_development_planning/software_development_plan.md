## 1. 目的と適用範囲

### 1.1 目的
本書は、仮想 Therac-25 Simple に搭載されるソフトウェアの開発プロセスを IEC 62304 の要求事項に従って計画し、その実施方法を定義することを目的とする。

### 1.2 適用範囲
- 対象ソフトウェア: Therac-25 Simple Beam Interlock Software(TH25S-CORE)
- 対象バージョン: 1.0.0
- 安全クラス: **C**
- 本計画は、ソフトウェア開発の開始からリリースまでのすべての活動に適用する。

## 5. システム設計及び開発との関連(箇条 5.1.3)

- 本ソフトウェアは、仮想 Therac-25 Simple のビームインターロック機能を担う。仮想プロジェクトのため、システムレベル成果物(システム要求仕様、システムアーキテクチャ)は学習目的で簡略化し、SRS §3 のトレーサビリティで対応付ける。
- システムレベルのハザード(放射線過剰照射)は ISO 14971 リスクマネジメントファイル(RMF-TH25S-001)に統合する。

## 6. ソフトウェア開発標準・方法・ツール計画(箇条 5.1.4 ― クラス B, C)

### 6.1 コーディング規約
- 使用言語: **C11**(ISO/IEC 9899:2011、`-std=c11`、拡張無効)
- 適用規約: MISRA C:2012 を第一参考とし、CERT C を補助とする(学習プロジェクトのため逸脱は許容するが、安全関連ユニットには努力目標として適用)
- 静的解析: コンパイラの厳格警告(`-Wall -Wextra -Wpedantic -Wshadow -Wconversion -Wsign-conversion -Wcast-align -Wnull-dereference -Wdouble-promotion`)を警告ゼロで通すことを必須とする。

### 6.2 開発ツール
| カテゴリ | ツール名 | バージョン | 用途 |
|---------|---------|----------|------|
| コンパイラ | GCC / Clang | C11 対応版 | ビルド |
| ビルドシステム | CMake | 3.20 以上 | ビルド構成 |
| 試験フレームワーク | CppUTest | 4.0(SOUP-001) | ユニット試験 |
| 構成管理 | Git | 2.x | バージョン管理 |
| 課題追跡 | GitHub Issues | — | 問題報告(PRB)・変更要求(CR) |
| CI/CD | GitHub Actions | — | 自動ビルド・試験・文書検証 |

## 7. ソフトウェア統合及び統合試験の計画(箇条 5.1.5)

- 統合戦略: **ボトムアップ**。UNIT-001 CommonTypes → UNIT-003 SafetyInterlock → UNIT-002 TreatmentSequencer の順に結合する(被依存ユニットを先に確立)。
- 統合環境: PC ホスト単体(CMake + CppUTest)。実ハードウェアは存在しない。

## 8. ソフトウェア検証の計画(箇条 5.1.6)

### 8.1 検証アプローチ
各フェーズ成果物に対し、レビュー・解析・試験のいずれかを定義する。クラス C のため、詳細設計・ユニット・結合・システムの各レベルで試験を必須とする。

### 8.2 検証方法一覧
| 成果物 | 検証方法 | 基準 |
|--------|---------|------|
| SRS | ピアレビュー、トレーサビリティ確認 | 全要求が一意・検証可能 |
| アーキテクチャ(SAD) | 設計レビュー | SRS との整合 |
| 詳細設計(SDD) | 設計レビュー(クラス C 必須) | 実装可能性・異常系網羅 |
| ユニット | CppUTest 試験、厳格警告ゼロ | 分岐網羅、正常・境界・異常系 |
| 結合 | 結合試験(ユニット間 IF の動作) | IF 網羅 |
| システム | システム試験(シナリオ) | SRS 網羅 100% |

## 9. ソフトウェアリスクマネジメント計画(箇条 5.1.7)

- リスクマネジメントは ISO 14971 に従い、ソフトウェアリスクマネジメント計画書(SRMP-TH25S-001)で詳細を定義する。
- Therac-25 の事故原因(モード/機構不整合、操作順序競合、カウンタオーバーフロー、暗号的エラー)を起点にハザード HZ-001〜HZ-003 を識別し、リスクコントロール手段 RCM-001〜RCM-004 を SRS・設計・試験へ紐付ける。

## 14. 共通ソフトウェア欠陥の識別と回避(箇条 5.1.12 ― クラス B, C)

C 言語に固有の共通的欠陥類型と回避策を以下に定義する。

| 欠陥類型 | 回避策・検出手段 |
|---------|---------------|
| バッファオーバフロー | 固定長配列の境界明示、可変長文字列処理を持たない設計 |
| ヌルポインタ参照 | 全公開関数の冒頭で引数 NULL チェック、`-Wnull-dereference` |
| 整数オーバフロー | 飽和カウンタ(`th25s_safe_counter_t`)で巻き戻りを構造的に排除(RCM-003) |
| 未初期化変数 | 厳格警告(`-Wall -Wextra`)、初期化子の明示 |
| 暗黙の型変換・桁落ち | `-Wconversion -Wsign-conversion -Wdouble-promotion` を警告ゼロで通す |
| 競合状態(順序依存) | 明示的状態機械による操作順序の構造的強制(RCM-001) |

参照: CWE、CERT C Coding Standard。
