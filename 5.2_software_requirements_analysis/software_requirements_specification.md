> 本プロジェクトは学習目的の仮想プロジェクトである。題材は Therac-25 放射線過剰照射事故であり、事故原因に対応するリスクコントロール手段を要求事項として明示する。

## 1. 目的と適用範囲

本書は、仮想 Therac-25 Simple に搭載される TH25S-CORE の要求事項を IEC 62304 箇条 5.2 に基づいて定義し、後続の設計・実装・試験の基礎とする。本ソフトウェアは、操作者の治療操作を受け、ビーム照射の可否を安全に判定するビームインターロック機能を担う。

### 1.1 用語と略語
| 用語 | 定義 |
|------|------|
| SRS | Software Requirements Specification(ソフトウェア要求仕様書) |
| RCM | Risk Control Measure(リスクコントロール手段) |
| HZ | Hazard(ハザード) |
| ターンテーブル | ビーム経路上の機構(散乱箔 / X線ターゲット)を切り替える回転台 |

## 3. システム要求事項からソフトウェア要求事項への展開(箇条 5.2.1)

仮想 Therac-25 Simple のシステム要求「治療モードに整合した状態でのみビームを照射すること」を、ソフトウェア要求 SRS-001〜SRS-010 および性能・入出力要求へ展開する。割付は「9. トレーサビリティマトリクス」に示す。

## 4. ソフトウェア要求事項(箇条 5.2.2)

各要求事項は、一意の ID・記述・優先度・検証方法・関連を持つ。

### 4.1 機能及び能力要求事項(箇条 5.2.2 a)

| ID | 要求事項(種別) | 優先度 | 検証方法 | 関連 |
|----|----------------|-------|---------|------|
| SRS-001 | 治療モードとして電子モード・X線モードを選択できる(機能) | 必須 | 試験 | UNIT-002 |
| SRS-002 | 治療シーケンスは IDLE→モード選択→処方設定→ターンテーブル確定→READY→ビームオン の順序でのみ進行し、順序を逸脱した操作は拒否する(機能) | 必須 | 試験 | RCM-001, HZ-002 |
| SRS-003 | 治療モードを再選択した場合、処方およびターンテーブル確定を破棄し、再確定を強制する(機能) | 必須 | 試験 | RCM-001, HZ-002 |
| SRS-004 | ビームオン要求は READY 状態でのみ受け付ける(機能) | 必須 | 試験 | RCM-001 |
| SRS-005 | エネルギはモード別の許容範囲(電子 1.0〜25.0 MeV / X線 5.0〜25.0 MV)内でなければならず、範囲外は拒否する(機能) | 必須 | 試験 | RCM-002 |
| SRS-006 | ターンテーブル位置(電子位置 / X線位置 / フィールドライト位置)を確定できる(機能) | 必須 | 試験 | UNIT-002 |
| SRS-007 | ビームオン時、治療モードとターンテーブル位置の整合を、シーケンサから独立した判定で確認し、不整合なら照射を拒否する(機能) | 必須 | 試験 | RCM-002, HZ-001 |
| SRS-008 | 線量は許容範囲(0.01〜10000.0 cGy)内でなければならず、範囲外は拒否する(機能) | 必須 | 試験 | RCM-002 |
| SRS-009 | ビームオン整合性チェックの実施回数を計数し、計数値がオーバーフローした場合はビームオンを拒否する(機能) | 必須 | 試験 | RCM-003, HZ-003 |
| SRS-010 | すべてのエラーは、エラーコードと人間可読のメッセージを伴って通知する(機能) | 必須 | 試験 | RCM-004 |
| SRS-101 | ビームオン要求の整合性判定は同期的に完了し、戻り値で結果を返す(性能) | 必須 | 試験 | UNIT-002, UNIT-003 |

| ID | 入出力名 | 方向 | 値域・形式 |

| SRS-I-003 | ターンテーブル位置 | 入力 | 列挙 {UNKNOWN, FIELD_LIGHT_POS, ELECTRON_POS, XRAY_POS} |
| SRS-I-004 | 操作要求(モード選択 / 処方設定 / 位置確定 / READY / ビームオン / abort) | 入力 | 関数呼出 |

|----|------------------|----------|-------|---------|
| SRS-ALM-001 | 安全違反による FAULT 遷移 | 整合性判定の不合格・カウンタオーバーフロー | 高 | エラーコード戻り値 + 状態遷移 |
| SRS-ALM-002 | 人間可読エラーメッセージ | 全エラー発生時 | 中 | `th25s_error_message()` 文字列 |

### 4.5 セキュリティ要求事項(箇条 5.2.2 e)

本シンプルプロジェクトはネットワーク機能・認証機能を持たず、PC ホスト単体で動作する。セキュリティ要求は適用対象が限定的であるため、本版では「外部入力(引数)に対する防御的検証(NULL チェック・値域検証)」のみを SRS-005 / SRS-008 / SRS-010 に含めて扱う。

### 4.6 ユーザビリティ要求事項(箇条 5.2.2 f)

SRS-010 により、すべてのエラーは人間可読のメッセージを伴う。Therac-25 の "MALFUNCTION 54" のような暗号的表示が操作者の誤判断とバイパス常態化を招いた教訓に対応する(RCM-004)。

### 4.7 データ定義及びデータベース要求事項(箇条 5.2.2 g)

| データ | 型 | 範囲・単位 |
|--------|---|----------|
| エネルギ(電子) | double | 1.0〜25.0 MeV |
| エネルギ(X線) | double | 5.0〜25.0 MV |
| 線量 | double | 0.01〜10000.0 cGy |
| 整合性チェックカウンタ | uint32_t | 0〜上限値(飽和) |

永続化(データベース)は持たない。状態はプロセスメモリ上の構造体で保持する。

### 4.8 設置及び受入要求事項(箇条 5.2.2 h)

CMake によりビルドし、`ctest` で全ユニット試験が合格することを受入条件とする(詳細は UTPR §6)。

### 4.9 運用及び保守の方法に関する要求事項(箇条 5.2.2 i)

エラーコードと状態を戻り値・取得関数で参照できる。診断的な追加ログ機能は本版では持たない。

### 4.10 IT ネットワーク関連要求事項(箇条 5.2.2 j)

ネットワーク機能を持たないため適用外。

### 4.11 ユーザによる保守要求事項(箇条 5.2.2 k)

ユーザ保守操作は持たない。abort によるシーケンスの初期化のみを提供する。

### 4.12 規制要求事項(箇条 5.2.2 l)

学習目的の仮想プロジェクトのため、実際の規制要求は適用しない。IEC 62304 クラス C のプロセス要求を疑似的な規制要求として全面適用する。

## 5. リスクコントロールに関連する要求事項(箇条 5.2.3)

| ID | リスクコントロール手段(RCM) | 対応するハザード | 関連 SRS |
|----|----------------------------|---------------|---------|
| SRS-RCM-001 | TreatmentSequencer の明示的状態機械により、ビームオン前提条件(順序)を構造的に強制する。モード再選択時はターンテーブル確定をリセットする。 | HZ-002 | SRS-002, SRS-003, SRS-004 |
| SRS-RCM-002 | SafetyInterlock が、TreatmentSequencer から論理分離された独立した判定として、モード・エネルギ・線量・ターンテーブル位置の整合を最終確認する。 | HZ-001 | SRS-005, SRS-007, SRS-008 |
| SRS-RCM-003 | 整合性チェックカウンタを飽和カウンタとし、オーバーフロー時に 0 へ巻き戻さず、ビームオンを拒否する。 | HZ-003 | SRS-009 |
| SRS-RCM-004 | すべてのエラーコードに人間可読のメッセージを対応付け、暗号的なエラー表示を排除する。 | HZ-001, HZ-002, HZ-003(横断) | SRS-010 |

## 6. 医療機器リスク分析の再評価(箇条 5.2.4)

要求事項定義中に新たなハザードは識別されなかった。HZ-001〜HZ-003 はリスクマネジメントファイル(RMF-TH25S-001)§4 に記録済みである。

## 7. ソフトウェア要求事項の更新(箇条 5.2.5)

システム要求が更新された場合、本 SRS を更新し、影響を関連ドキュメント(SAD、SDD、各試験文書)へ波及させる。変更手順は構成管理計画(SCMP)に従う。

## 8. 要求事項の検証(箇条 5.2.6)

各要求事項は以下の基準を満たすことをレビューで確認した。

- [x] システム要求事項への実装可能性

- [x] 明確で、試験可能であること(値域・条件が数値で明示されていること)
- [x] 一意に識別可能であること(SRS-xxx)
- [x] リスクコントロール手段の実装に使用できること(§5 参照)
