# 第 I 部 計画

## 3. ソフトウェアユニットの結合(箇条 5.6.1)

### 3.1 結合戦略
- 採用戦略: **ボトムアップ**。
- 採用理由: 依存方向が単方向(SAD §4.2)であるため、被依存ユニットを先に確立すると上位ユニットの結合時にスタブが不要となる。

### 3.2 結合ステップ
| ステップ | 結合対象ユニット | 前提 | 使用スタブ・ドライバ |
|---------|---------------|------|------------------|
| 1 | UNIT-001 CommonTypes(単体) | — | CppUTest 試験ドライバ |
| 2 | UNIT-003 SafetyInterlock + UNIT-001 | Step 1 完了 | CppUTest 試験ドライバ(IF-U-003 を実呼出) |
| 3 | UNIT-002 TreatmentSequencer + UNIT-003 + UNIT-001 | Step 2 完了 | CppUTest 試験ドライバ(IF-U-001/002 を実呼出) |

> 本プロジェクトは単一ライブラリ・3 ユニットの最小構成であり、結合は `libth25s_core.a` のリンクとして実現される。スタブは使用せず、各ユニット間 IF は実呼出で結合する。

## 4. ソフトウェア結合の検証(箇条 5.6.2)

| 結合ステップ | 検証内容 | 検証日 | 記録 ID |
|------------|---------|-------|---------|
| 2 | IF-U-003(SafetyInterlock→CommonTypes)が SAD §5 の定義どおり接続 | 2026-05-14 | ITPR-REV-001 |
| 3 | IF-U-001(Sequencer→SafetyInterlock)・IF-U-002(Sequencer→CommonTypes)が SAD §5 の定義どおり接続 | 2026-05-14 | ITPR-REV-001 |
| 全体 | 構成管理下の正しいバージョン(v1.0.0 相当)のユニットが結合されている | 2026-05-14 | ITPR-REV-001 |

## 5. ソフトウェア結合試験(箇条 5.6.3)

ユニット間インタフェース(IF-U-001〜003)の動作を、結合された状態で検証する。各試験ケースは SRS / RCM に紐付ける。結合試験は UTPR と同一の CppUTest スイート(`th25s_tests`)上で実行する。

- [x] 結合状態で要求機能が実現されること(機能試験)

- [x] リスクコントロール手段(RCM)が結合状態で機能すること

## 8. 回帰試験の実施(箇条 5.6.6)

- 不具合修正・設計変更時は、影響範囲を解析し、CI(`build-test.yml`)で全結合試験を自動再実行する。
- 本バージョン 1.0.0 では変更要求がなく、回帰試験の対象事象は発生していない。

## 9. 結合試験記録の内容(箇条 5.6.7)

各試験記録には、試験 ID・対象ビルド・試験環境・手順・入力・期待結果・実結果・合否・逸脱処置を含める。本書 §11 にサマリを記録する。

## 10. ソフトウェア問題解決プロセスの使用(箇条 5.6.8)

結合試験で発見した問題は IEC 62304 箇条 9(SPRP-TH25S-001)に従って記録・分析・是正し、リスクマネジメントプロセスへ入力する。本バージョンでは問題は発見されなかった。
