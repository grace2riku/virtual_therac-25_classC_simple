# 第 I 部 計画

## 3. ソフトウェア要求事項を検証する試験の設定(箇条 5.7.1)

システム試験は、SRS のすべての要求事項が実装されていることを **試験により検証** する。本プロジェクトでは全 SRS 要求が試験で検証可能であり、レビュー・解析のみで検証する要求はない。試験ケース ST-001〜007 は、操作者の治療シナリオを模した一連の操作列として構成し、UTPR の試験ケース群によって実現する。

## 4. 試験方針

### 4.1 試験環境
- 試験対象: TH25S-CORE v1.0.0(`libth25s_core.a`)
- 試験ハーネス: CppUTest 4.0 による操作者シナリオドライバ(`th25s_tests`)
- 周辺機器: なし(PC ホスト単体の仮想シミュレータ)
- 実機・実患者: 存在しない(学習目的の仮想プロジェクト)

### 4.2 試験種別
| 種別 | 目的 |
|------|------|
| 機能試験 | 正常な治療シナリオでビームオンに到達すること |
| 異常系試験 | 不整合・順序違反・範囲外でビームが拒否されること |
| リスクコントロール試験 | RCM-001〜004 がシステムレベルで有効に機能すること |
| ユーザビリティ試験 | エラーが人間可読のメッセージで通知されること |

## 5. ソフトウェア問題解決プロセスの使用(箇条 5.7.2)

システム試験中に発見された不具合は、IEC 62304 箇条 9(SPRP-TH25S-001)に従って記録・分析・是正する。是正に伴う変更は影響範囲を評価し、該当試験を再実行する。本バージョンでは不具合は発見されなかった。

## 6. 変更後の再試験(箇条 5.7.3)

試験中にソフトウェア変更が生じた場合は、影響範囲を解析してシステム試験を選択的に再実行する。安全関連機能(RCM 検証ケース ST-003〜005)は変更種別によらず必ず再実行する。CI(`build-test.yml`)により全試験を push/PR ごとに自動再実行する。

## 8. 試験ケース定義

### 8.1 試験ケース一覧

| 試験 ID | 種別 | 対象要求 | 試験シナリオ概要 | 期待結果 | 実現する UT |
|--------|------|---------|--------------|---------|------------|
| ST-001 | 機能 | SRS-001, SRS-004, SRS-006, SRS-101 | 電子モードの正常治療: モード選択→処方→電子位置確定→READY→ビームオン | BEAM_ON に到達(READY 状態でのみビームオンが受け付けられることを含む = SRS-004) | UT-002-02 |
| ST-002 | 機能 | SRS-001, SRS-006 | X線モードの正常治療: モード選択→処方→X線位置確定→READY→ビームオン | BEAM_ON に到達 | UT-002-07(前半フロー), UT-003-02 |
| ST-003 | リスクコントロール | SRS-007 / RCM-002, HZ-001 | モード/ターンテーブル不整合(X線モード+電子位置)でビームオン要求 | MODE_TURNTABLE_MISMATCH、FAULT へ遷移しビーム拒否 | UT-002-14, UT-003-03 |
| ST-004 | リスクコントロール | SRS-002, SRS-003 / RCM-001, HZ-002 | 設定完了(READY)後にモードを編集 → 処方・位置確定が破棄され、再確定なしには READY へ進めない | モード再選択で MODE_SELECTED へリセット、再確定スキップは SEQUENCE_VIOLATION | UT-002-07, UT-002-08 |
| ST-005 | リスクコントロール | SRS-009 / RCM-003, HZ-003 | 整合性チェックカウンタ上限到達状態でビームオン要求 | COUNTER_OVERFLOW、FAULT へ遷移しビーム拒否(チェックはバイパスされない) | UT-002-17, UT-001-18 |
| ST-006 | 異常系 | SRS-005, SRS-008 | 範囲外エネルギ・範囲外線量の処方を投入 | ENERGY/DOSE_OUT_OF_RANGE で拒否、状態は進行しない | UT-002-10, UT-002-11, UT-003-08, UT-003-09 |
| ST-007 | ユーザビリティ | SRS-010 / RCM-004 | 全エラーコードのメッセージ取得 | すべて非空・人間可読のメッセージが返る(暗号的表示の排除) | UT-001-20, UT-001-21 |

### 8.2 試験手順の詳細

各試験ケースは、`tests/` 配下の CppUTest ケースとして手順・入力・期待結果が機械的に記述されている(UTPR §7.2 参照)。再実行は `ctest --test-dir build --output-on-failure` による。
