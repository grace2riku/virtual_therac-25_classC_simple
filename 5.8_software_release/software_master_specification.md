## 7. リリースソフトウェアの作成方法の文書化(箇条 5.8.5)

### 7.1 ビルド環境
| 項目 | 値 |
|------|----|
| OS | macOS または Linux |
| コンパイラ | GCC または Clang(C11 / C++17 対応版) |
| ビルドツール | CMake 3.20 以上 |
| 試験フレームワーク | CppUTest 4.0(pkg-config 経由) |

### 7.2 ビルド手順
```bash
# 製品ライブラリ + 試験のビルド
cmake -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build

# ユニット・結合・システム試験の実行
ctest --test-dir build --output-on-failure

# 製品ライブラリのみをビルドする場合(CppUTest 不要)
cmake -B build-lib -DTH25S_BUILD_TESTS=OFF
cmake --build build-lib
```

### 7.3 成果物リスト
| ファイル名 | 用途 |
|----------|------|
| `libth25s_core.a` | 製品ライブラリ(ビームインターロック安全コア) |
| `th25s_tests` | ユニット・結合・システム試験実行ファイル(検証用、製品には含めない) |

## 10. ソフトウェアリリースの再現可能性の保証(箇条 5.8.8)

### 10.1 リリースの再現可能性
- 再構築に必要なソース・ビルドスクリプト一式がタグ `v1.0.0` にアーカイブされている。
- ビルド手順(§7.2)は決定論的であり、同一環境で同一の `libth25s_core.a` を再生成できる。
- CI(`build-test.yml`)が push/PR ごとにビルドと全試験を再実行し、再現性を機械的に担保する。

### 10.2 配布時の完全性確保
- 本プロジェクトは学習目的でありバイナリ配布を行わない。完全性は Git のコミットハッシュとタグにより担保する。
