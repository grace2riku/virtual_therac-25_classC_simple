## 3. 意図する使用及び安全に関連する特性(ISO 14971 箇条 5.2)

### 3.1 意図する使用
- 対象(仮想): 放射線治療装置のビーム照射可否判定。
- 使用環境: 医療機関の治療室(本プロジェクトでは PC ホスト単体の仮想シミュレータ)。
- 操作者: 放射線治療技師。

### 3.2 安全に関連する特性
| 項目 | 記述 |
|------|------|
| エネルギーを与えるか | はい(高エネルギー放射線。仮想シミュレータ上のモデル) |
| ソフトウェア制御 | あり(クラス C) |
| 操作ミス可能性 | あり(治療パラメータ入力・操作順序) |
| 継続使用時間 | 1 治療あたり数分(仮想) |

## 4. ハザード・ハザード状況・危害の識別(ISO 14971 箇条 5.4)

### 4.1 ハザード一覧

| ハザード ID | ハザード分類 | 記述 | 想定される危害 | ソフトウェア寄与 |
|-----------|-----------|------|------------|--------------|
| HZ-001 | 機能的(放射線) | 治療モードとターンテーブル位置が不整合な状態でビームが照射される | 放射線過剰照射による死亡又は重傷 | 有 |
| HZ-002 | 機能的(放射線) | 操作順序依存により安全整合性チェックが実施されないままビームオンに至る | 不整合状態での照射 → 過剰照射 | 有 |
| HZ-003 | 機能的(放射線) | 整合性チェック回数カウンタのオーバーフローにより安全チェックがバイパスされる | 不整合の見逃し → 過剰照射 | 有 |

> 上記 3 ハザードは Therac-25 の実際の事故原因(N. G. Leveson & C. S. Turner, 1993)に対応する。HZ-002 は当時のタイミング競合(race condition)を、本プロジェクトでは単一スレッドの操作順序依存バグとして教材化したものである。

### 4.2 事象シーケンス

本節では §6.1 リスク評価表で参照する事象シーケンスを `EV-NNN` のラベル付きで定義する。
事象 ID `EV-` は **事象シーケンス(Event Sequence)** の意で、原因 → 中間状態 → ハザード状況 → 危害の経路を一意に識別する(CLAUDE.md / README §略語 に登録)。

#### EV-001(HZ-001 の主たる発現経路)

```
モード/機構整合判定の欠如 → X線モードで電子位置のまま → X線ターゲット非挿入で
高出力ビーム照射 → 患者への過剰照射
```

#### EV-002(HZ-002 の主たる発現経路)

```
設定完了後の素早いモード編集 → 古いターンテーブル状態が引き継がれる →
不整合状態でビームオン → 過剰照射
```

#### EV-003(HZ-003 の主たる発現経路)

```
整合性チェックカウンタが巻き戻る → カウンタ値依存の安全チェックがバイパス →
不整合を見逃してビームオン → 過剰照射
```

#### EV-004(HZ-001 / HZ-002 / HZ-003 を横断する誤判断要因)

```
暗号的エラーメッセージ("MALFUNCTION 54" 型) → 操作者が原因を識別できず →
エラー表示をそのままバイパスする運用習慣が定着 → 不整合状態でビームオンを継続
→ 過剰照射(EV-001 / EV-002 / EV-003 のいずれの最終ハザードにも寄与する)
```

EV-004 は単独のハザードではなく、上記 3 ハザードの発生可能性を底上げする **横断的要因** として §6.1 表に独立行で計上する(対策 RCM-004 は ISO 14971 §7.1 の警告手段に分類され、判定は補助的位置づけとなる。詳細は [IEC62304_QA.md §QA-001](../IEC62304_QA.md#qa-001-rmf-61-リスク評価コントロール一覧の見方) を参照)。

## 5. リスク推定(ISO 14971 箇条 5.5)

### 5.1 重大度と発生可能性の評価基準

#### 重大度(Severity)
| 段階 | 区分 | 例 |
|------|------|-----|
| S5 | 破局的 | 死亡、永続的重傷 |
| S4 | 重大 | 重傷、入院 |
| S3 | 重度 | 医療介入を要する傷害 |
| S2 | 軽度 | 一時的で軽微な傷害 |
| S1 | 無視可能 | 一時的な不快感 |

#### 発生可能性(Probability)
| 段階 | 区分 | 頻度の目安 |
|------|------|----------|
| P5 | 頻繁 | > 10⁻³/使用 |
| P4 | 可能性大 | 10⁻³〜10⁻⁴ |
| P3 | 時々 | 10⁻⁴〜10⁻⁵ |
| P2 | 稀 | 10⁻⁵〜10⁻⁶ |
| P1 | ほとんどない | < 10⁻⁶ |

### 5.2 リスクマトリクス

|      | S1 | S2 | S3 | S4 | S5 |
|------|----|----|----|----|----|
| P5 | 中 | 高 | 高 | 許容外 | 許容外 |
| P4 | 低 | 中 | 高 | 高 | 許容外 |
| P3 | 低 | 中 | 中 | 高 | 高 |
| P2 | 無視 | 低 | 中 | 中 | 高 |
| P1 | 無視 | 低 | 低 | 中 | 中 |

許容方針: 「許容外」「高」は必ずリスクコントロールを実施する。「中」「低」は ALARP 原則を適用する。

### 6.1 リスク評価・コントロール一覧

| ハザード ID | 事象 ID | S | P | 推定リスク | RCM ID | コントロール種別 | 残留 S | 残留 P | 残留リスク | 判定 |
|-----------|--------|---|---|----------|--------|-------------|-------|-------|----------|------|
| HZ-001 | EV-001 | S5 | P4 | 許容外 | RCM-002 | 設計安全(独立整合判定) | S5 | P1 | 中 | 許容 |
| HZ-002 | EV-002 | S5 | P4 | 許容外 | RCM-001 | 設計安全(状態機械) | S5 | P1 | 中 | 許容 |

### 6.2 コントロール種別の優先順位(ISO 14971 箇条 7.1)

1. 設計による本質的安全(RCM-001, RCM-002, RCM-003 — 状態機械・独立判定・飽和カウンタにより危険状態を構造的に成立させない)
2. 保護手段(RCM-002 の独立判定は多重防御としても機能する)
3. 安全に関する情報(RCM-004 — 明確なエラー表示。単独では不十分なため補助的位置づけ)

## 8. 全体的な残留リスクの評価(ISO 14971 箇条 8)

### 8.1 残留リスクの総合評価

- [x] すべての特定ハザード(HZ-001〜003)に対して RCM が実装・検証された。
- [x] 個別残留リスクはすべて許容基準(中以下)内である。
- [x] RCM 実装による新たなハザードは識別されなかった(SRMP §5.2)。
- [x] 残留異常(ANOM)はリリース時点で存在しない(SMS §4 参照)。

### 8.2 ベネフィットとリスクの対比

本プロジェクトは学習目的の仮想プロジェクトであり、臨床的ベネフィットの定量評価は対象外とする。教育的観点では、Therac-25 の事故原因に対応するリスクコントロール手段を IEC 62304 プロセスで実装・検証する一連の体験を提供することが本プロジェクトの価値である。総合的な残留リスクは許容可能と判定する。
