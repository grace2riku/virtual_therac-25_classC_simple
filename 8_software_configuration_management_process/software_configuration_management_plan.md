## 3. 構成識別(箇条 8.1)

### 3.1 構成アイテム識別手段の確立(箇条 8.1.1)
すべての構成アイテムは、一意の `CI ID`・名称・種別・バージョン(Git タグまたはコミットハッシュ)を持つ。

- バージョン管理システム: Git(SHA-1 コミットハッシュ + タグ)
- リリースタグ規則: `v1.0.0` 形式
- ドキュメント: ファイル冒頭にドキュメント ID + バージョンを明記
- 構成アイテム一覧は [`configuration_item_list.md`](./configuration_item_list.md) で一元管理する

### 3.2 SOUP の識別(箇条 8.1.2)
SOUP-001 CppUTest について、名称・供給元・バージョン・ライセンス・入手日を構成アイテム一覧(CIL §5)に記録する。

### 3.3 システム構成ドキュメンテーションの識別(箇条 8.1.3)
| ドキュメント種別 | 管理方法 |
|--------------|---------|
| ソフトウェアマスタ仕様書(SMS) | リリースタグ `v1.0.0` と紐付け |
| ビルド構成(CMakeLists.txt) | リポジトリ内で版管理 |
| CI 設定(.github/workflows/) | リポジトリ内で版管理 |

## 4. 変更制御(箇条 8.2)

### 4.1 変更要求の承認(箇条 8.2.1)
すべての構成アイテムへの変更は、承認された変更要求(CR)に基づいて実施する。

| CR 区分 | 承認者 |
|--------|-------|
| 軽微(誤字、コメント) | 開発者A(開発責任者として) |
| 中程度(非安全関連機能) | 開発者A(CCB 簡易審議を擬制) |
| 重大(安全関連・アーキテクチャ変更・SOUP 変更) | 開発者A(CCB 正式審議を擬制) |

#### 4.1.1 単独開発下の独立性擬制
本プロジェクトは単独開発のため、CCB・品質責任者・レビュアは開発者A が兼任する。これは Therac-25 事故の主要因の一つである「単独開発者 + 独立レビューの不在」を **意図的に擬制で補う** という学習目的に直結する。独立性の代替手段:

1. **審議インターバル**(中程度以上の変更): 重大区分は 24 時間以上のインターバルを設ける(CCB-TH25S-001 §5.4)
2. **自己レビューチェックリスト**(Pull Request 上で実施)
3. **CI による機械的検証**(docs-check: 構造・lint・リンク・日付 / build-test: ビルド・全試験)

### 4.2 変更の実装(箇条 8.2.2)
- フィーチャブランチで作業、Pull Request を経由して統合する。
- コミットメッセージに CR ID(`CR-NNNN`)を含める。
- ビルド・試験は CI(`build-test.yml`)で自動実行する。

### 4.3 変更の検証(箇条 8.2.3)
| 変更規模 | 最低限の検証 |
|---------|-----------|
| 軽微 | 自己レビュー、該当ユニット試験 |
| 中程度 | 上記 + 結合試験 + 該当 RCM 検証 |
| 重大 | 上記 + システム試験 + リスク再評価(SRMP §6) |

### 4.4 変更のトレーサビリティ(箇条 8.2.4)
以下の連鎖を維持する。

```
問題報告(PRB)/変更要求 → CR → コミット → マージ → ベースライン → リリース
```

- コミットメッセージに CR ID(例: `CR-0001: ...`)
- Pull Request 本文に問題報告 ID・関連 SRS・関連 RCM を記載
- リリースノート(GitHub Releases)に含まれる CR を列挙

## 5. 構成状態記録(箇条 8.3)

### 5.1 ベースライン設定タイミング
- 要求凍結時(SRS 承認時)
- 設計凍結時(SDD 承認時)
- 各リリース時(`v1.0.0` タグ付与時)

### 5.2 状態記録の内容
| 項目 | 内容 |
|------|------|
| ベースライン ID | `BL-YYYYMMDD-NNN` 形式 |
| ベースライン日 | ISO 8601 日付 |
| 含まれる CI とバージョン | 構成アイテム一覧(CIL)のスナップショット |
| 関連 CR | CR ID 一覧 |
| 承認者 | 開発者A |

### 5.3 保管
ベースライン記録およびベースラインに含まれる成果物は、Git リポジトリ(タグ)で保管する。
